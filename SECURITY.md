# Security

The stack is closed by default. This page says what protects what, what
you must still do yourself, and how to report a vulnerability.

## Layers

| Component | Exposure | Protection |
|---|---|---|
| Caddy | ports 80/443 on the host | TLS (Let's Encrypt for a real `PUBLIC_HOST`, internal CA for localhost), HSTS and hardening headers, redirects HTTP to HTTPS |
| Orion-LD | `https://orion.<host>` through Caddy only | `X-API-Key` must equal `ORION_API_KEY`; anything else gets 401 before reaching the broker. Internally, only members of the compose `internal` network can reach port 1026 |
| MongoDB (Orion's store) | internal network only | authentication on (`MONGO_USER` / `MONGO_PASSWORD`); Orion-LD connects with those credentials |
| InfluxDB | `https://influx.<host>` through Caddy only | its own token authentication (`INFLUX_TOKEN` is the admin token; create read-only tokens for consumers in the UI) |
| Airflow | `https://<host>` through Caddy only | its own login (`AIRFLOW_ADMIN_PASSWORD`), Fernet-encrypted connections, JWT secret for the API |
| Postgres (Airflow's store) | internal network only | password (`POSTGRES_PASSWORD`) |
| Secrets | `.env`, mode 600, gitignored | generated by `scripts/gen-secrets.sh`; gates receive them only as `${VAR}` references |

`docker-compose.dev.yml` publishes the backends on 127.0.0.1 without TLS for
local development. It is a development convenience: never use it on a
machine reachable from a network you do not control.

## What you still have to do

- **Name the host**: set `PUBLIC_HOST` and `ACME_EMAIL` before the first start
  on a server, and point DNS for `orion.` and `influx.` subdomains at it.
- **Consumer tokens**: `INFLUX_TOKEN` is the admin token the pipelines use.
  Issue read-only bucket tokens to consumers from the InfluxDB UI instead of
  sharing it.
- **Rotate**: `ORION_API_KEY` is a single shared key. Change it in `.env` and
  `docker compose up -d caddy` to rotate; consumers update their header.
  For per-consumer identities, put a FIWARE PEP proxy (Wilma) with Keyrock in
  front of the broker; that is on the roadmap (M5) and Caddy stays as the
  TLS layer in front of it.
- **Back up** the four data volumes; the secrets in `.env` are needed to read
  them again.
- **Update images**: the compose file pins major versions; rebuild regularly.

## Threat model in one paragraph

An attacker on the internet sees only Caddy. Without the API key the broker
answers 401; without a token InfluxDB answers 401; without a login Airflow
shows a form. An attacker on the host's Docker network can reach the
backends directly, so the host itself must be trusted and patched. Anyone
with `.env` has everything: treat it like a private key.

## Reporting a vulnerability

**Do not open a public issue.** Two private channels, either is fine:

- GitHub's private vulnerability reporting on this repository (Security →
  Report a vulnerability). It creates a private advisory thread, which is the
  easiest place to work on a fix and to credit you in the advisory.
- E-mail **sstamatopoulos@epu.ntua.gr**.

What helps: the version or commit, which component (a gate, the framework, the
compose stack, the proxy), and what an attacker gains. A proof of concept is
welcome but not required.

What to expect: an acknowledgement within a few working days, and an honest
answer about severity and timing. This is research software maintained
alongside other work, not a product with an on-call rota — if something needs
fixing urgently and nobody has replied, say so in the thread and escalate by
e-mail.

Please give us a reasonable chance to fix an issue before describing it
publicly. If a vulnerability is already public or being exploited, say that
immediately and we will skip the quiet part.

### Scope

In scope: this repository's code and its shipped configuration — the gates,
the framework, `docker-compose.yml`, `proxy/Caddyfile`, the scripts.

Out of scope, though still worth telling us about: vulnerabilities in Airflow,
Orion-LD, MongoDB, InfluxDB, Caddy or a gate's driver library (report those
upstream), and anything that requires `.env`, which by design grants
everything.
